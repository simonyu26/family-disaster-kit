# 每日自動備份（獨立 Apps Script 專案）

這個資料夾是「防災小隊備份」專案的程式，和 `gas/Code.gs`（App 用的公開後端）**分開放、分開部署**。
分開的原因：Apps Script 的權限整個專案共用。備份需要讀寫雲端硬碟，如果放進公開後端，App 的公開入口也會拿到整個雲端硬碟的權限（工程顧問諮詢，`reviews/backup-consult.md`）。

## 每天做什麼

每天 03:00（台北）：

1. 複製家庭資料試算表（檔名 `防災備份_試算表_日期`）
2. 下載本 repo `main` 分支的程式碼壓縮檔（`防災備份_程式碼_日期.zip`）
3. 存白名單內的指令碼屬性（`防災備份_屬性_日期.json`，只含 `SPREADSHEET_ID`、`INVENTORY_SHEET_NAME`、`CHAR_HEADER_NAMES`；**不存通行碼與任何金鑰**）
4. 清掉舊備份：14 天內全留；更舊的只留 8 週內的週日那份；其餘移到垃圾桶（30 天內可救回）。只處理檔名符合上面格式的檔。

存放位置：雲端硬碟「防災生存整備系統_開發備份」底下的「每日自動備份」資料夾。資料夾內的 `防災備份_上次結果.txt` 記錄最近一次每一項成功或失敗。

安全檢查：備份資料夾若有分享給別人或開放連結，會停止備份並寄失敗通知（試算表含家人健康資料）。

## 第一次設定（擁有者操作，約 5 分鐘）

1. 到 [script.google.com](https://script.google.com) 新增專案，命名「防災小隊備份」。
2. 左側「專案設定」：勾選「在編輯器中顯示 appsscript.json」。
3. 把本資料夾的 `appsscript.json` 與 `Backup.gs` 內容分別貼進編輯器的同名檔案並儲存（預設的 `程式碼.gs` 可改名成 `Backup.gs` 或刪掉）。
4. 「專案設定 → 指令碼屬性」新增：
   - `SPREADSHEET_ID`：和 App 後端專案的同名屬性相同
   - `INVENTORY_SHEET_NAME`、`CHAR_HEADER_NAMES`：App 後端專案有設的話照抄（選填）
5. 上方函式選單選 `dailyBackup`，按「執行」。第一次會跳授權畫面，應只出現三項：查看與管理雲端硬碟檔案、連線到外部服務、管理觸發條件。按允許。
6. 到雲端硬碟確認「每日自動備份」資料夾裡有今天的三個備份檔與 `防災備份_上次結果.txt`。
7. 函式選單改選 `setupBackupTrigger`，按「執行」。
8. 左側「觸發條件」：點剛建立的觸發條件，把「失敗通知設定」改成「立即通知我」，儲存。

不需要「部署」，也不要部署成網頁應用程式。

## 之後更新程式

repo 的 `gas-backup/Backup.gs` 有改動並合併後，照第 3 步重新貼上、儲存即可，觸發條件不用重建。
